# 服务端自定义网络目标

CrewRouter 的受校验出站请求会拒绝命中当前拒绝表的私网、回环、链路本地、元数据、多播和部分特殊用途地址，并在每次请求前校验目标。直连请求会把 socket 固定到本次校验得到的地址；通过已配置 HTTP/SOCKS 代理的请求会把代理隧道目标固定到该地址。两种方式都保留原始主机名用于 HTTP Host 与 TLS 证书验证。自动跟随重定向的直连调用会重新校验每个跳转目标。

Bark 与 CPA 请求不跟随重定向，也不经过环境代理。其他供应商流量仍可使用后台配置的 HTTP/SOCKS 代理；代理服务本身是单独的信任目标，应限制其地址、访问权限和网络出口。

确实需要连接私有服务时，可在 CrewRouter 服务进程环境中配置精确主机允许列表：

- `CR_BARK_PRIVATE_ORIGINS`：允许的私有 Bark origin。
- `CR_CPA_PRIVATE_ORIGINS`：允许的私有 CPA origin。

列表使用逗号分隔，必须写完整 origin，包含协议、主机和端口，例如 `http://127.0.0.1:8317`；不支持通配符、CIDR 或路径。IPv6 遵循 URL 格式，例如 `http://[::1]:8317`。新增或修改环境变量后重启 CrewRouter 服务。只允许实际需要的目标；允许某个 DNS origin 也意味着该名称可解析到的私有地址会被信任。

Bark 和 CPA 的公网地址必须使用 HTTPS。只有精确列入对应允许列表的 origin 才可使用 HTTP，以兼容本机或内网服务。

精确允许的 DNS origin 代表信任该名称当前解析到的地址，后续请求会重新解析并固定本次结果。允许列表不能替代出站网络控制；应在主机或容器网络层禁止应用访问未授权的私网和云元数据地址。
