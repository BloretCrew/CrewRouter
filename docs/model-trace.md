# 模型归因（ModelTrace）

CrewRouter 将 [ModelTrace](https://github.com/xqy2006/ModelTrace) 的数字指纹算法接入模型检测。第三方算法、挑战和统计指纹库固定到发布版本，版权与 MIT 许可证随静态资源分发。

## 检测方式

- **手动归因**：复制三个独立挑战，发送给同一个待测模型，再粘贴完整回答进行浏览器本地计算。计算不会调用模型，也不会上传回答。外部模型生成回答会消耗其对应额度。
- **主动检测**：选择已配置且有权访问的模型和脱敏 Key，确认请求预算及费用后，由服务端执行三条独立挑战。检测会消耗真实上游额度，并按实例的用量规则结算积分。

进入页面、打开对话框、查看结果、刷新进度和查看历史均只读取数据。检测由用户按需启动；补测需要再次确认并创建新任务。

## 对话框与后台任务

启动后可以关闭对话框或切换页面。服务端继续执行已确认的有限预算任务，模型库顶部显示任务进度。重新打开任务可查看进度或结果。

关闭对话框只隐藏界面。“取消检测”停止后续挑战并中止在途传输；上游能否停止内部推理由远端实现决定，已发送请求可能产生费用。

模型归因任务与会话总结在顶部分别展示。关闭完成卡片只隐藏通知，检测历史继续保留。服务重启后的中断任务保留状态，由用户决定是否重新检测。

## 如何理解结果

结果为**候选库内、均匀先验下的闭集概率**。库外模型也会归入最相似的已有候选。概率较高表示在该库中较匹配，实际模型身份仍需要额外证据。

请结合有效回答数量、候选库覆盖范围、采集来源、库版本、检测环境与时间判断。只有一到两条有效回答时，结果以参考状态展示。拒答、截断或有效数字不足的回答单独列出诊断。

上游原项目报告系统提示词会影响模型偏好，Claude Code 场景可能存在较大偏差。内置库模型标签和采集渠道来自原项目声明，属于来源元数据。

主动检测针对冻结的供应商、模型、协议与 Key，使用无历史、无工具的独立挑战。完整客户端会话、Fusion 和响应插件的行为具有各自适用范围。

客户端请求模型、路由模型、上游响应模型与指纹候选分别保留。系统不会根据归因结果自动修改模型名、停用供应商或拦截正常调用。

## 数据与安全

指纹库随 CrewRouter 发布，从本机或同源加载。用户 Key 在服务端解密使用，界面与任务结果只返回脱敏标签。

自动任务保存目标快照、各挑战诊断、版本化结果和用量信息，默认不保存原始回答。任务读写受用户、Team 与供应商归属检查限制。

## 预算、结算与运行边界

每次检测最多三条挑战；首期同时限制每用户一个运行任务、每供应商两个任务，以及每用户每天二十次任务。每条挑战执行前重新核验授权与配置，并预留余额或免费配额。

已知用量按系统六位积分精度结算，Responses 缓存输入使用既有缓存折扣。明确的鉴权或限流拒绝且未返回 usage 时退还预留并停止后续挑战。已发送后断连、超时、无法解析或未知用量时保留该条预算预留，标记“用量未知”，当前版本需要另行人工对账。

结算数据库故障会停止后续挑战，以有界退避重试账务写入。取消停止生成，账务仍继续幂等结算。服务关闭时保留未完成状态，重启仅恢复结算并标记中断。

首期执行队列面向单服务进程。多实例共享数据库的协调恢复、脚本模式动态 Key、自建库、批量/定时检测及 Codex Guard 留作后续范围。

## 开发验收

实现一致性、权限、请求预算、取消、状态恢复与账务使用离线样本、模拟上游和隔离数据库验证。浏览器验收覆盖实际点击、输入、启动、关闭、导航、刷新、取消和历史查询。

模拟测试与算法对照测试验证实现行为。真实供应商的归因准确性需要单独批准额度并通过控制变量采集评估。发布、推送、生产迁移及重启均需另外确认。
