# 插件信任、安装与执行边界

## 当前执行模式

后端 `main.js` 默认不执行。只有在管理员审查插件代码并显式设置 `CR_TRUST_IN_PROCESS_PLUGINS=1` 后，插件才会运行。当前后端插件在 CrewRouter 主进程中执行；Node VM、权限清单、超时和任务重试都不是对恶意代码的 OS 安全隔离。

只有可审查、可信的后端代码才可启用。未知来源或无法审查的插件应保持禁用。若部署场景要求对不可信插件提供技术隔离，必须先由部署层提供独立低权限 OS 身份/容器、最小文件系统挂载、网络出口控制和资源限制，并通过故障/越权测试；当前应用不提供该保证。

## 商店包校验

从允许的 HTTPS 商店源安装时，服务器要求包 SHA-256 并与下载内容比对，校验 ZIP 结构、manifest 和插件 ID。安装确认提交的包摘要和权限快照也会与服务器重新获取的元信息/包内容比较；不一致时要求管理员重新查看权限。

SHA-256 只证明下载的归档与商店元数据中的摘要相同。若商店元数据和归档由同一发布方控制，哈希**不构成发布者身份签名**。当前插件包协议没有已部署的发布者公钥信任根、签名撤销或密钥轮换，因此不能声称已验证发布者身份。商店审核（若有）也不等于独立安全审计。

安装页面会显示权限、SHA-256、进程内执行警示，并要求管理员确认权限；具有后端权限的包还要求单独确认信任风险。管理员确认不代表插件代码已安全。

## 更新与回滚

商店更新会保留插件原有启用状态；已禁用插件不会因更新自动启用。升级前应检查新版本权限变化和代码来源。若摘要缺失、无效或与下载包不符，安装失败。

## 任务与事件

- `tasks:register` 提供数据库持久任务记录、幂等、租约、重试与状态；handler 仍在受信任主进程执行。超时/AbortSignal 不能杀死同步阻塞或忽略取消的代码。
- `events:subscribe` 是字段白名单、版本化的进程内 best-effort 通知，不是 durable message broker；跨重启可靠处理用持久任务。
