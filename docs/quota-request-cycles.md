# 逐请求额度采集与额度周期分析

## 功能范围

每个实际上游调用建立独立尝试记录，绑定当时的供应商与额度账户。一次逻辑请求可能因重试、切 Key、切供应商或 Fusion 子调用产生多次尝试。平台请求数与上游尝试数分别统计。

默认采用持久队列异步采集：请求结束后查询对应账户的额度，保存任务、查询状态、观测时间及前后样本。请求开始时引用最近有效额度；尚无基线时创建基线任务。查询失败、限流、凭据或配置切换、未启用额度接口都有明确状态。记录失败不会阻断原请求响应。

仅查询实际上游调用所使用的 Key 或共享订阅账户。凭据以服务端稳定身份关联，历史不保存明文 API Key、OAuth Token 或完整供应商响应。多 Key 查询相互独立，共享订阅多个供应商按账户去重。

## 配置

后台 → 设置 → 数据保留 → 请求额度采集，可配置：

| 配置 | 默认值 | 说明 |
|---|---:|---|
| 启用逐请求额度采集 | 启用 | 供应商还需启用额度查询并配置有效查询模式 |
| 采集模式 | 异步 | 精细模式增加请求前后查询等待；请确认上游频率和延迟成本 |
| 对账等待秒数 | 60 | 达到100%后等待计费延迟与晚到请求更新 |
| 最大采集尝试次数 | 5 | 达到上限保存失败状态 |
| 队列处理间隔 | 2000ms | 控制持续工作频率 |
| 每批任务数 | 10 | 最大并发领取量 |
| 任务租约 | 120秒 | 异常退出后可以恢复处理 |

配置通过 `/api/admin/request-quota-config` 校验并保存，普通用户不能修改。任务持久化领取采用数据库锁和租约，网络查询期间释放数据库事务。

## 额度变化窗口

每个账户、额度类型、单位和窗口分别检测变化。百分比按上游原始精度保存，展示舍入不参与变化检测。余额按明确计量单位分析。

变化窗口保存基线、确认变化的样本、金额差额或百分点变化，以及期间的用户和请求。连续相同值的采样也保留，后续变化可以关联此前尚未观察到消费的请求。

- `certain`：请求执行时间完整落在观测区间内。
- `candidate`：跨区间边界的请求。
- `pending`：采样时尚未结束的请求。

这些标识表示时间归集证据。并发请求、上游计费延迟和平台外调用仍可能影响实际消费归属。系统展示区间观测消耗及请求/Token/积分贡献，精确单请求供应商成本需要上游逐请求账单支持。

充值、重置、额度调整、同时间戳修正和历史回补分别记录。对账会修订关联与报告版本，旧版本保留审计。

## 完整额度周期

使用率从已用0%到100%形成耗尽周期。余额型仅在有效且固定的总额度下换算使用率。无限额度、未知总额或缺失数据不会生成虚假完整周期。

首次观测已超过0%、采样缺口、未确认边界或周期中调整会标注部分覆盖。周期重置后开始新周期；重置前未耗尽也有报告。达到100%先进入待对账，再根据覆盖质量确认完整或部分周期。

报告包含：

- 额度期初、期末、变化时间线、重置与调整、耗尽与确认时间。
- 逻辑请求和尝试数、成功/失败/取消/重试、流式、确定/候选/待确认关联。
- 输入、输出、缓存、总及加权Token、积分、未知/估算用量。
- 延迟P50/P95/P99、吞吐、请求时间范围。
- 用户、请求时Team、模型、项目、客户端、平台Key和会话贡献。
- 请求→上游尝试→前后额度样本的追溯与权限过滤导出。

“供应商额度”在多维分析中继续作为附加信息，勾选和取消保持原维度、指标、时间范围和请求统计口径。

## 查看与权限

统计总览提供折叠周期摘要；供应商额度卡片的“查看周期”打开专属详情。按账户选择周期，查看变化时间线、贡献维度、分页请求及单条样本。

管理员查看授权范围内的周期和用户贡献。普通用户只查看自身请求、用量和贡献比例，其他用户明细不返回。Team隐藏额度、供应商可见性、模型授权撤回同样限制周期接口、样本和导出。

周期样本、尝试和关联事实长期保留，不依赖短期用量明细的保留天数。启用前已清除的历史缺少精确上游账户与时间，无法补齐逐请求归属。

## 验证与上线

测试采用本地专用数据库的独立 schema 和模拟上游，结束移除测试 schema。真实账户高频采样、账单对齐、线上迁移与服务重启需要单独授权。

```sh
QUOTA_TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:18579/crewrouter_quota_test \
  node server/scripts/test-request-quota-capture.js
QUOTA_TEST_DATABASE_URL=postgresql://postgres@127.0.0.1:18579/crewrouter_quota_test \
  node server/scripts/test-quota-cycle-analysis.js
node server/scripts/test-quota-request-context.js
node scripts/test-provider-quota-cycle-browser.js
```

浏览器命令需要隔离演示服务和Chrome，通过 `BLORA_TEST_URL` 和 `BLORA_CDP_URL` 指定地址。不要直接使用共享环境进行测试写入。

### 运行质量与规模边界

采集使用独立最大4连接的数据库池，连接等待1秒、SQL5秒、锁2秒，避免挤占计费连接。默认异步模式网络路径最多等待250毫秒，已识别精细模式最多等待25秒；超时明确降级并按顺序继续后台写入，不能保证数据库持续不可用期间仍完整记录所有请求。后台持久操作达到1000上限时拒绝新增操作并记录质量告警。

进程实例有独立心跳。崩溃遗留的 running 尝试按失效实例恢复为中断、用量未知，结束时间采用推断证据；这类请求只作为候选关联，排除实际延迟百分位。

正常样本增量推进，历史回补才重建序列；无变化的 worker 不扫描历史。隔离性能验收覆盖1000样本及30秒预算，极大周期的报告聚合与审计发布仍可能受SQL预算限制，生产容量需结合实际并发继续评估。

JSON界面导出遍历全部分页并验证报告版本，最多40000条；超过上限明确拒绝截断下载。服务端JSON导出每段安全上限10000条并提供版本绑定游标，适合更大周期的分段导出。历史报告可查看，历史版本导出明确拒绝，以保证汇总和请求版本一致。
