OpenRouter Fusion API 研究报告

基于公开信息与官方文档整理 | 更新于 2026 年 6 月

1. 概述

Fusion API 是 OpenRouter 推出的服务器端多模型“审议”（deliberation）系统。

核心理念：将一个 prompt 并行发送给多个模型（Panel），由 Judge 模型分析输出差异，然后由调用模型基于分析生成最终高质量回答。

目标：在复杂研究、批判性思考等任务上达到或超越前沿单模型性能，同时降低成本。

本质：Mixture-of-Agents + Judge + Synthesis 的打包实现，对开发者透明易用。

2. 工作流程

  1. 用户请求：发送普通 chat completion 请求（model: "openrouter/fusion" 或附加工具）。
  2. 外层模型决策：判断是否需要 Fusion（可强制调用）。
  3. Panel 并行执行（最多 8 个模型）：
    • 每个模型独立处理相同 prompt
    • 启用 web_search + web_fetch 等工具
    • 产生多样化输出
  4. Judge 分析：
    • 输出结构化 JSON：共识、矛盾、盲点、独特洞见等
  5. 最终合成：外层模型基于 Judge 分析生成最终回答。

递归保护：Panel 和 Judge 不会递归调用 Fusion。

3. 使用方式

最简单方式

model: "openrouter/fusion"

高级自定义

  • 通过 plugins 或工具参数指定 panel 模型、judge 模型、preset 等
  • 支持 general-high、budget 等预设
  • 作为工具调用：{"type": "openrouter:fusion"}
  • Fusion Chatroom 测试：https://openrouter.ai/fusion

4. 性能与成本

Panel 类型 表现 成本特点
Frontier（高端） 超越单个前沿模型 较高
Budget（经济） 接近 Fable 5 等前沿模型 约一半成本

DRACO 基准：在 100 个复杂研究任务上表现突出，尤其适合需要多视角、工具辅助的场景。

5. 注意事项

  • 适合复杂、研究型任务；简单任务可能不划算
  • 成本 = 所有 panel + judge + 外层调用总和
  • 支持 streaming、OpenAI/Anthropic 兼容
  • 可自定义 temperature、max_tool_calls 等参数
