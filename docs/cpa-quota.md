# CPA 额度查询

CrewRouter 支持通过 CPA v8 管理接口查询账号额度，可使用无插件自动模式或已加载的额度插件。现有手动刷新、定时查询、后台额度详情和控制台额度展示共用该适配器。

## 供应商配置

在后台编辑供应商，启用额度查询，选择 CPA 额度查询（服务器管理接口），并在同一窗口填写：

- **CPA 管理地址**：填写 CrewRouter 服务能够访问的可信 CPA 地址。公网地址必须使用 HTTPS；本机或内网地址（例如 `http://127.0.0.1:8317`）只有在服务器环境变量 `CR_CPA_PRIVATE_ORIGINS` 中精确列出协议、主机名/IP 和端口后才允许。多个 origin 用逗号分隔，不支持通配符或网段；IPv6 地址使用 URL 方括号格式。Docker 中的 `127.0.0.1` 指向 CrewRouter 容器自身。
- **CPA 管理密钥**：CPA 管理接口的密钥，加密存储。编辑时留空保留原值，已保存密钥不会返回浏览器。
- **CPA 额度插件 ID（可选）**：留空启用无插件自动模式；填写时继续使用该已加载插件查询，插件需要支持目标账号的额度查询。
- **CPA 账号（必选）**：填写管理地址和密钥后，点击「加载 CPA 账号」，在下拉列表中选择目标账号。编辑时密钥留空即可使用已保存的密钥加载账号。已禁用账号不可选择。

账号列表仅返回账号标签、类型、索引和禁用状态，Token 等凭据不会传到浏览器。加载失败可重试；暂无账号时，请先在 CPA 登录。设置 `CR_CPA_PRIVATE_ORIGINS` 后需要重启 CrewRouter 服务。

点击保存，所有配置随供应商设置一起持久化，然后查询额度。查询直接读取供应商配置，无需因普通配置变更重启。保存和每次查询都会校验目标地址；请求禁止重定向，并将连接固定到本次校验得到的 DNS 地址，以避免管理密钥泄露。请求直连 CPA，不经过环境代理。地址只允许管理员配置，请使用可信 CPA 服务，并通过出站防火墙限制访问范围。

Bark 与 CPA 私有端点允许列表的格式和网络限制见[服务端自定义网络目标](outbound-endpoint-security.md)。

已有插件 ID 和账号索引会自动回填。切换查询方式时隐藏 CPA 字段，并保留原配置。此前只配置过环境变量的供应商需要在编辑窗口补充管理地址和管理密钥。

仅使用插件模式时需要获取插件 ID，可通过 CPA `GET /v8/management/plugins` 获取；该插件需要支持目标供应商的额度查询。凭据索引通过 CPA `GET /v8/management/credentials` 获取。上述接口均需要管理密钥。

## 查询模式

- **无插件自动模式**：`plugin_id` 留空（JSON 配置也可省略此字段），`auth_index` 必填。根据账号凭据自动读取账号类型，Codex/Claude 支持主动查询；其他账号仅读取 CPA 已记录的被动额度，有有效数据才展示。被动额度可能需要账号先产生请求，不保证实时更新，也不代表所有供应商都支持主动查询。
- **插件模式**：填写 `plugin_id` 时，继续调用 `GET /v8/management/plugins/{plugin_id}/quota?auth_index={auth_index}`，额度查询能力取决于已加载插件。

独立额度窗口分别展示，主额度使用剩余比例最低的窗口。支持 CPA 的 camelCase 和 snake_case 额度字段，也支持数值摘要中的 `balance` 或 `remaining`。无有效数据时明确提示，不展示虚构额度。v0 接口不做自动降级。

本适配器使用管理员指定的账号关联。配置前请确认该账号应向哪些用户或 Team 展示，现有供应商权限控制继续生效。该功能不自动导入 OAuth 账号，不改变请求路由或额度耗尽后的模型调度。

## 测试

`npm run test:quota-usage` 包含 CPA 归一化、隔离 HTTP 服务查询、鉴权、错误状态及重定向测试。真实额度查询需要运行 CPA 并配置管理地址、管理密钥和账号索引；仅插件模式需要加载对应额度插件。Codex/Claude 主动查询及其他账号的被动额度读取仍需按实际账号联调验证。
