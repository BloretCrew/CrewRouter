2. Claude Code

TypeScript / Anthropic Messages API

定义语言：Zod v4（z.strictObject + lazySchema 包装），经 src/utils/zodToJsonSchema.ts 转 JSON Schema。
线上协议：纯 Anthropic Messages API —— tools 数组（input_schema）、 assistant 的 tool_use block、结果以 user 消息内的 tool_result block 回传。 全库无 chat/completions 路径。
工具注册：src/tools.ts → getAllBaseTools()；实现位于 src/tools/<Name>Tool/。

2.1 tools 数组元素格式（BetaTool）

{
  "name": "Read",
  "description": "<prompt() 生成的完整描述文本>",
  "input_schema": { "type": "object", "properties": {...}, "required": [...] },  // JSON Schema
  // 条件附加：
  "strict": true/false,            // 见 zodToJsonSchema 结果
  "cache_control": { "type": "ephemeral" },          // prompt 缓存
  "defer_loading": true,           // ToolSearch 延迟加载工具
  "eager_input_streaming": true
}

2.2 调用与结果回传

// assistant 发起调用（content block）
{ "type": "tool_use", "id": "toolu_01...", "name": "Bash", "input": { "command": "ls" } }

// 结果回传（user 消息内的 content block）
{ "type": "tool_result", "tool_use_id": "toolu_01...", "content": "…输出…", "is_error": false }

  timeout: semanticNumber(z.number().optional()).describe('Optional timeout in milliseconds'),
  description: z.string().optional().describe('Clear, concise description of what this command does'),
  run_in_background: semanticBoolean(z.boolean().optional()).describe('Set to true to run in background'),
  dangerouslyDisableSandbox: semanticBoolean(z.boolean().optional()).describe('...'),
  // _simulatedSedEdit 为内部字段，序列化前 omit，不暴露给模型（防绕过权限）
}));

Edit（src/tools/FileEditTool/types.ts）

const inputSchema = lazySchema(() => z.strictObject({
  file_path:  z.string().describe('The absolute path to the file to modify'),
  old_string: z.string().describe('The text to replace'),
  new_string: z.string().describe('The text to replace it with (must be different from old_string)'),
  replace_all: semanticBoolean(z.boolean().default(false).optional()).describe('Replace all occurrences (default false)'),
}));

Grep（src/tools/GrepTool/GrepTool.ts）

const inputSchema = lazySchema(() => z.strictObject({
  pattern: z.string().describe('The regular expression pattern to search for'),
  path: z.string().optional().describe('File or directory to search in (rg PATH)'),
  glob: z.string().optional().describe('Glob pattern to filter files'),
  output_mode: z.enum(['content','files_with_matches','count']).optional(),
  '-B': ..., '-A': ..., '-C': ..., '-i': ..., type: ..., head_limit: ..., multiline: ...
}));
特殊点： ① Bash 内部字段 _simulatedSedEdit 从模型可见 schema 剔除；② <system-reminder> 以纯文本注入 tool_result/user 消息（提示层协议）；③ StructuredOutput 合成工具用 z.object({}).passthrough() 承载任意 结构化 JSON（SDK 场景替代 XML 标签）；④ 未发现 XML 形式的 function-calling 文本协议。

3. OpenAI Codex CLI

Rust / OpenAI Responses API

定义语言：Rust 结构体 + schemars::JsonSchema derive；工具对象为 ToolSpec 枚举（tools/src/tool_spec.rs）。
线上协议：仅 OpenAI Responses API（POST /v1/responses，SSE 或 WebSocket）。 Chat Completions 已被移除（wire_api = "chat" 报错）。
工具注册：core/src/tools/spec_plan.rs add_core_tool_sources()； 单个 handler 在 core/src/tools/handlers/。

3.1 ToolSpec 四种工具形态

// ① function（结构化 JSON 工具）
{ "type": "function", "name": "exec_command", "description": "...", "strict": false,
  "parameters": { "type":"object", "properties":{...}, "required":["cmd"], "additionalProperties":false } }

// ② namespace（命名空间容器，内含多个 function）
{ "type": "namespace", "name": "clock",
  "tools": [ { "type":"function","name":"curr_time",... }, { "type":"function","name":"sleep",... } ] }

// ③ custom / freeform（文本协议工具，如 apply_patch）
{ "type": "custom", "name": "apply_patch", "description": "... FREEFORM tool, do not wrap in JSON ...",
  "format": { "type": "grammar", "syntax": "lark", "definition": "start: begin_patch hunk+ end_patch ..." } }

// ④ hosted / 服务端执行
{ "type": "tool_search", "execution": "client", ... }
{ "type": "web_search", "external_web_access": true, "search_context_size": "medium", ... }

3.2 调用与结果回传（Responses API）

// assistant 输出（SSE 解析为 ResponseItem）
{ "type": "function_call", "name": "exec_command", "namespace": null,
  "arguments": "{...}", "call_id": "..." }        // arguments 是 JSON 字符串
{ "type": "custom_tool_call", "name": "apply_patch", "input": "*** Begin Patch...", "call_id": "..." }  // 纯文本
{ "type": "tool_search_call", ... } / { "type": "web_search_call", ... }

// 结果回传（追加到下一轮 input）
{ "type": "function_call_output", "call_id": "...", "output": "..." }
{ "type": "custom_tool_call_output", "call_id": "...", "name": "apply_patch", "output": "..." }

9. 文本协议工具对比

多数 harness 在结构化 JSON 工具之外，还保留一种纯文本协议工具用于批量文件编辑， 其中最典型的是源自 Codex 的 apply_patch。

9.1 apply_patch 信封格式（Codex / OpenCode / OpenClaw / Grok-Build-codex 共用）

*** Begin Patch
*** Add File: hello.txt
+Hello world
*** Update File: src/app.py
@@ def greet():
-print("Hi")
+print("Hello, world!")
*** Move to: src/greet.py        <!-- 可选重命名 -->
*** Delete File: obsolete.txt
*** End Patch
Header含义后续内容
*** Add File: <path>新建文件以 + 开头的内容行
*** Delete File: <path>删除文件无
*** Update File: <path>就地修改可选 *** Move to:，然后一个或多个 hunk
hunk以 @@ 开头（可带上下文标注如 @@ def method():）+ 新增 / - 删除 / 空格 上下文行；可选 *** End of File

9.2 其他文本/XML 约定

  • Hermes 的 <untrusted_tool_result>：外部来源工具结果包一层 XML 定界符， 内嵌定界符做中性化（下划线→连字符）防逃逸，防止间接提示注入。

11. 结论与关键文件索引

11.1 核心结论

  1. Schema 定义语言 4 类：Zod（Claude Code）、schemars derive（Codex、Grok Build）、 TypeBox（OpenClaw）、Effect Schema（OpenCode）；Hermes 用纯 dict，Qwen Code 直接写 JSON Schema。 最终都产出一份标准 JSON Schema（draft-07）。
  2. 线上协议 2 大族：Anthropic Messages（Claude Code）与 OpenAI 系（Codex Responses、 Grok Build 双轨、Hermes Chat、Qwen Code 兼容、OpenCode AI SDK 多 provider）；OpenClaw 为最完整的 多协议适配层。
  3. 工具结果统一约定：OpenAI 系为 role:"tool" + tool_call_id（Chat）或 function_call_output + call_id（Responses）；Anthropic 系为 tool_result + tool_use_id。 arguments 一律是 JSON 字符串。
  4. 渐进披露（tool_search）成为标配：除 OpenCode 外，6 个 harness 都有延迟工具发现机制， 控制 token 成本并保持 KV cache 稳定。
  5. 文本协议并存：apply_patch（Codex 系 4 家）与各种 XML 定界符约定（Hermes、Claude Code 等）， 与结构化 JSON 工具互补。
