# API Key 配置与提示词一致性复核（2026-10-25）

本轮检查 API Key 管理、注入提示词和默认条目初始化。复现仅使用合成数据、真实函数/路由提取、独立缓存替身或全新 Unix socket PostgreSQL；以下应用缺陷不构成已确认的入侵利用证据。没有读取生产凭据、连接生产数据库、调用真实供应商或自动修改历史数据。

## 提示词修改会覆盖并发禁用

旧 PUT 先读取条目，再把未指定字段从旧快照合并到整行 UPDATE。隔离复现：改名请求读取 enabled=true 后暂停，另一个请求成功禁用，再恢复改名请求，最终条目被重新启用。两个请求替换初始为空的 Key 绑定集合时，也会分别插入自己的选择，最终混合 `[11,12]`，而不是完整采用最后一个请求。

现在修改、快捷开关、绑定替换及删除使用单一事务，先按属主锁提示词父行，再读写其字段及绑定；空子集合也有可串行化的锁。绑定的 Key 在事务中按 ID 顺序锁定并校验属主，Co-Key 管理成员不能把他人的 Key 当作自己的绑定目标。查询响应所需字段也在同一事务读取，失败全部回滚。

原接口用 `parseInt` 加过滤归一化 Key ID，`['invalid']` 被静默转成空数组，导致原本指定 Key 的条目变成用户内全局；`'12junk'` 会被当作 Key 12。现在整批拒绝非法值，返回 400，原绑定保留；接受有效的数字和十进制数字字符串、去重排序，只有显式空数组表示全局。绑定他人 Key 返回 403，非属主操作返回 404。

## 提示词撤销不能依赖 Key 的进程缓存

旧缓存将拼接后的提示词保留 60 秒。全局改指定 Key 或反向变化时，只失效前后绑定 Key 的并集，遗漏其余受影响 Key；删除在落库前失效，正在读取的请求还可能在失效后回填旧内容。另一个进程的 Map 不受本进程失效影响。

现在缓存不保存提示词内容；冷热请求都读取本次提示词到局部变量，再完成原 Key 生命周期检查，最后构造请求独有的 `apiUser`。这样不会把提示词放回共享缓存，也不增加生命周期刷新次数。CRUD 在提交后失效该用户 Key 缓存，回调异常仅记录，不能把已提交操作误报为未执行。

生效边界是本次提示词 SQL 的读取快照：已经读到旧提示词的在途请求可能继续使用旧值，提交后的新读取会获得最新状态。补丁不撤销已发送的上游请求。提示词查询失败仍保留原行为：记录错误，本次请求不注入；没有把提示词当作鉴权边界。

普通“全局”只指当前 Key 属主的全部 Key。拼接函数从 API Key 数据库属主读取条目，不从当前网页登录成员读取，符合 Co-Key 的属主语义；本轮没有复现普通用户间的跨账号注入。SQL 虽兼容 `user_id IS NULL`，当前建表要求该列 NOT NULL，不能把这个查询分支当作正常库存在全用户条目的证据。

## 默认条目初始化与 OOBE 事务

旧默认播种是先查空、后独立插入；真实隔离库确认两次读取均为空时允许双插，当前结构没有用户/默认条目的唯一约束。现在播种先短事务锁用户行，再重查是否有任意条目，仅空时插入一次。使用 `FOR NO KEY UPDATE`，与子表外键的 `KEY SHARE` 兼容；不删除来源未知的历史重复条目。

函数自借连接时负责 BEGIN、COMMIT、ROLLBACK 和释放；显式传入的事务 client 仍归调用方所有。PassPort 注册沿用原事务。OOBE 静态复核发现创建管理员后曾另借连接播种：新用户尚未提交，其他连接不可见，单连接池还会等待已被自己占用的槽位。现在复用管理员创建 client，并用 SAVEPOINT 隔离可选播种失败，使失败不会中止剩余初始化步骤。

保留原产品语义：已有条目（包括禁用条目）不补种；删除全部条目后，下一次请求仍可能重新播种默认条目。要停止注入应保留并禁用条目。本轮没有把“删除全部”改成永久关闭，也没有据此认定自动补种是攻击者写入。

## 模型队列与 Co-Key 管理撤销

真实 `api_key_models` 仅有 `(api_key_id, model_id)` 组合唯一键。原队列替换事务不锁 Key 父行：两个请求都能删除空集合，再分别插入不同模型，最终合并队列，而 `current_model_id` 只对应一个写者。原共享设置还在事务外预检权限，成员撤销成功后，已通过预检的请求仍可继续修改。

现在全部 15 个既有 `:id` 写接口通过共同事务工具：先锁 API Key 父行，再用同一 client 复核成员/属主权限。工具缓冲状态码和 JSON；成功提交后实际响应并失效缓存，校验拒绝与异常都结束事务。回调只执行本地数据库操作。

覆盖的十项共享配置为：名称/虚拟模型、模型队列、Harness、Fusion、额度提醒、签名、启用状态、吞图、CrewRouter 指令和调度；另外覆盖成员添加、成员移除、主动退出、属主删除和属主标签。成员撤销和写入采用同一父行锁序：写入先拿锁则撤销等待其提交；撤销先提交则后续写入锁内复核返回 404。属主专属操作、内部 CrewRouter Key 的保护规则、原有成功响应形状保持。

成员移除只撤销管理关系，不轮换原始 API Key，也不能召回成员已经取得的凭据。若凭据曾暴露，应另行禁用/轮换 Key。个人显示排序使用独立用户投影，不参与这些共享设置事务。
