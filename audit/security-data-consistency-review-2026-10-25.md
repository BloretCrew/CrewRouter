# 数据一致性专项复核（2026-10-25）

本轮继续检查入侵后的余额、团队关系、兑换码和管理员身份写入。以下问题均由代码检查及合成数据复现支持；没有证据证明攻击者在事件中利用了这些路径，也不能用修复后的测试结果证明历史数据完整。

## 已确认的问题与修复

### 扣款工具的事务连接错绑

`server/utils/balance.js` 的 `deductBalance` 自行取得连接并执行 `BEGIN`，实际扣款却经 `pool.query` 执行。因此用户行锁不能覆盖完整扣款，发生错误时自有连接上的 `ROLLBACK` 也不能撤销已经提交的余额变更。隔离复现中，余额 10 扣除 7 后注入后续写入故障，旧实现返回失败但余额已经变为 3。

修复后，所有扣款 SQL 使用同一自有连接；外部事务客户端仍由调用者负责开始、提交、回滚及释放。自有事务提交后才触发预警和缓存失效；外部事务不得提前通知，由调用者在成功提交后负责。这是导出工具缺陷，当前检索没有找到其生产调用者，不能将它描述为已确认的线上计费入口。

### 团队归属投影与连接泄漏

飞书注册原先用连接池调用包含多条 SQL 的 `setUserTeam`，每条 SQL 各自提交，可能与管理员迁移交错，留下 `users.team_id` 和 `user_teams.team_id` 不一致。移除成员原先未先锁用户再核验归属，可能在用户迁入新 Team 后仍按用户 ID 清空新归属。管理员编辑还有拒绝取消最后管理员、空更新等分支，在活动事务内直接响应并归还连接，遗留事务和行锁。

归属变更现在使用事务客户端，既有 Team 先于用户行加锁；批量用户按 ID 排序加锁，再修改两份投影。飞书初始分配在同一事务内完成，若管理员已设置归属则保留。移除成员在锁内重新核验归属；删除有关联 Team 的既有拒绝行为继续保留。管理员编辑所有提前返回都先结束事务。

管理员编辑原先向缓存失效函数传入 HTTP 字符串 ID，而缓存按数值 ID 严格比较。现在在提交后传入数值 ID；回归使用真实缓存函数确认对应条目被删除。

### 并发取消最后两位管理员

原接口分别锁定两个目标用户，普通 `COUNT` 查询均能看到另一人仍是管理员。以恰有两个管理员的合成库同时执行两个降权请求，两者均返回成功，最终管理员数为零。

降权事务现在在任何 Team / User 行锁之前取得共同的 `pg_advisory_xact_lock`，锁键为 `CRWR / ADMN` 的两个整数命名空间。最终顺序为管理员集合锁 → Team → User → 检查及修改，提交或回滚自动释放。当前未找到用户删除实现；未来所有减少管理员的入口须遵守相同协议，直接数据库写入不受此应用协议保护。

### 删除兑换码会级联删除账本历史

旧单删和批删直接删除兑换码；两个外键的 `ON DELETE CASCADE` 会同时删除使用历史和退款余额明细，却不扣减 `users.refund_balance`。即使剩余明细金额为零，也会失去历史。此问题不需要攻击者篡改计数即可触发。

删除现在在事务内按 ID 排序锁定全部目标，只有使用计数恰为零、无使用历史、无余额明细才允许删除；任何一项有关联或计数异常，整批返回 409 并回滚。不会自动修补余额、重建历史或删除已消费到零的账本记录。若历史已被级联删除，当前快照不能恢复其内容，仍须外部凭证与可信备份对账。

### 遗留创建入口绕过校验

旧手工、批量创建接口没有采用新版生成接口的金额/次数验证，可接受负数等异常参数，依赖数据库静默舍入，使用 `Math.random`，没有批量上限，并错误地把 `max_uses=0` 改成 1。小写手工码与兑换时的大写规范也不一致。

三个创建 URL 现在共用校验，保留原响应结构，兼容蛇形/驼峰字段并拒绝冲突或非标量别名。金额必须为正且最多四位小数，金额上限 999999.9999；次数为 0 至 2147483647，其中 0 保留无限语义；批量为 1 至 1000；手续费范围为 0 至 9.9999。手工码去首尾空白并转大写，批量使用 `crypto.randomBytes`。无效输入统一返回 400；重复码返回 409。

兑换在用户及兑换码行锁内核对实际使用历史、不同用户数与 `used_count`，不一致返回 409 并暂停该次兑换，不根据不可信历史自动修复计数。批量设置可退款属性只影响后续兑换，历史手续费继续使用余额明细快照，这一行为未改变。

## 审计器补强

只读审计新增孤儿使用记录、同码同用户重复使用、余额明细缺少对应使用记录检查，并将零/NULL 面额、NULL 次数、负/NULL 手续费计入异常。新增字段进入完整性校验与退出码：发现异常为 1，缺少应有字段为 2。已完全级联删除的历史没有残存关联，不能依靠这些查询追溯发现。
